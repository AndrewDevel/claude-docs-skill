# Docusaurus — scaffolding bilingüe / bilingual scaffolding

Docusaurus es la base del sitio navegable. Es Node/React, así que encaja con el stack del equipo.
Esta guía describe **todo lo necesario** para instalarlo, correrlo y desplegarlo.

## 1. Estructura que se crea dentro de `/<repo>/docs`

```
docs/
├── package.json              # deps del sitio de documentación (aislado del repo principal)
├── docusaurus.config.js      # configuración del sitio (i18n es/en, tema, navbar)
├── sidebars.js               # 3 secciones: Técnica / Plataforma / API
├── docs/                     # contenido Markdown bilingüe
│   ├── intro.md
│   ├── tecnica/              # documentación técnica interna
│   ├── plataforma/           # guía de uso para cliente final (si aplica)
│   └── api/                  # referencia de API (si aplica)
├── src/css/custom.css
└── static/
    ├── img/
    │   ├── logo.png          # logo de la marca (navbar + social card)
    │   └── favicon.ico       # favicon multi-resolución
    └── openapi.json          # spec embebido (si aplica)
```

## Marca: favicon y logo / Branding: favicon and logo

Copia los assets de marca a `<repo>/docs/static/img/`:

1. **Si el repo ya tiene un logo/favicon propio** (busca en `public/`, `src/assets/`, `assets/`
   nombres como `favicon.*`, `logo*.png`, `*-icon.png`), reutilízalo: es lo más fiel a la marca.
2. **Si no**, usa los assets por defecto incluidos en
   `assets/docusaurus/img/` (logo de PagaCel) — cópialos a `static/img/`.

La config ya apunta a `favicon: 'img/favicon.ico'`, `navbar.logo.src: 'img/logo.png'` e
`image: 'img/logo.png'` (tarjeta social). Genera el `.ico` desde un PNG con
`convert icon.png -define icon:auto-resize=64,32,16 favicon.ico` (ImageMagick) o con PIL.
La paleta de `custom.css` ya está afinada a los colores de PagaCel (slate `#2D3142`, acento
`#7366ff`, cyan `#00B4D8`).

> El sitio de docs tiene su **propio** `package.json`, separado del `package.json` del proyecto,
> para no contaminar las dependencias de la app. Copiar la plantilla desde
> `assets/docusaurus/package.json`.

## 2. Instalar y correr

```bash
cd <repo>/docs
npm install
npm run start      # servidor local en http://localhost:3000 (idioma por defecto: es)
npm run build      # genera el sitio estático en docs/build
npm run serve      # sirve el build localmente
```

Las plantillas de `package.json`, `docusaurus.config.js` y `sidebars.js` están en
`assets/docusaurus/`. Cópialas y rellena los placeholders `{{PROJECT_NAME}}`, `{{REPO_URL}}`,
`{{GH_USER}}`, `{{GH_REPO}}`, `{{BASE_URL}}`.

## 3. i18n (español por defecto, inglés como locale)

En `docusaurus.config.js` el bloque i18n ya viene configurado:

```js
i18n: {
  defaultLocale: 'es',
  locales: ['es', 'en'],
  localeConfigs: {
    es: { label: 'Español' },
    en: { label: 'English' },
  },
},
```

Hay dos formas válidas de escribir bilingüe; usa una y sé consistente en el repo:

- **Patrón A (por defecto, recomendado para empezar):** cada página `.md` contiene ambos idiomas en
  secciones apiladas (`## Español` y `## English`). Sobrevive aunque no se configure i18n. Las
  plantillas de `assets/templates/` usan este patrón.
- **Patrón B (i18n nativo):** páginas espejo en `i18n/en/docusaurus-plugin-content-docs/current/`.
  Más limpio para sitios grandes, pero duplica archivos. Migrar a este patrón cuando el sitio crezca.

## 4. Sidebars (3 secciones que reflejan los tipos de doc)

`sidebars.js` define categorías. Incluir solo las que apliquen al repo:

```js
module.exports = {
  docs: [
    'intro',
    { type: 'category', label: 'Técnica / Technical', items: [{ type: 'autogenerated', dirName: 'tecnica' }] },
    { type: 'category', label: 'Plataforma / Platform', items: [{ type: 'autogenerated', dirName: 'plataforma' }] },
    { type: 'category', label: 'API', items: [{ type: 'autogenerated', dirName: 'api' }] },
  ],
};
```

Si el repo es backend-only, omite la categoría "Plataforma". Si no expone API, omite "API".

## 5. Despliegue a GitHub Pages

El workflow `assets/workflows/deploy-docs.yml` se copia a `<repo>/.github/workflows/deploy-docs.yml`.
Hace build del sitio y publica en GitHub Pages en cada push a `main` que toque `docs/`.

Requisitos en el repo de GitHub:
1. Settings → Pages → Source = **GitHub Actions**.
2. En `docusaurus.config.js`: `url`, `baseUrl` (`/{{GH_REPO}}/`), `organizationName: {{GH_USER}}`,
   `projectName: {{GH_REPO}}`.

El workflow ya incluye permisos `pages: write` e `id-token: write`.
